# Portfolio agent instructions

Scope: this repository. Read this file and any deeper AGENTS.md applying to files you change.

## Continuity and source access
- Read the current task, applicable instructions, affected source, relevant design records, and open PRs before recommending or changing work.
- Identify what is already implemented, assigned, or awaiting verification. Amend existing work where appropriate; do not duplicate or restart it.
- If an answer depends on a linked page, video, or file, read its substantive contents first. If inaccessible, stop that dependent work and request the contents. Repository source may be used when the user authorizes it.
- Name specific uncertainties. Do not invent approvals, implementation status, canon, or verification.
- Complete the authorized implementation and appropriate checks before producing extra plans or documentation.

## Presentation and identity
- Read docs/PORTFOLIO_DESIGN.md and affected rules in assets/portfolio-foundation.css. Keep that file the single authoritative stylesheet; scope project exceptions.
- Preserve project identities and approved artwork. Do not replace symbols, recolor all projects, introduce dependencies, or create competing design systems without explicit direction.
- Keep one persistent contextual PIXIE launcher at bottom right, with safe-area spacing and visible focus. Reuse the existing approved sigil and behavior; PIXIE is distinct from Rebirth.
- Preserve accessible typography, theme contrast, normal heading tracking, 48px controls, keyboard access, and reduced-motion behavior. Browser checks do not establish physical iPad/Safari/VoiceOver acceptance.
- External brand references are contextual sources, not automatic authority over this repository.

## Delivery
- Production is GitHub Pages from this repository. Vercel is for review previews. Do not change hosting, DNS, canonical URLs, or production routing as part of design work.
- For visual changes provide a direct Vercel URL to the affected page, not a dashboard or code file as a substitute for visual review.
- Keep review changes on a branch/PR until the user authorizes merge. Earlier release approval does not authorize unrelated future releases.
- Report what changed, checks performed, and remaining unverified items. Do not claim publication or preview availability without verifying it.

## Shared instructions across repositories
This file governs this portfolio; it does not override another repository's own instructions.
If another repository references shared ecosystem instructions, explicitly read the referenced file: a URL alone does not load or inherit instructions.
Keep local deployment, security, privacy, canon, and test requirements in the owning repository.
