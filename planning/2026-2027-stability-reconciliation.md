# Loptr Lab 2026 → 2027 Stability & Reconciliation Plan

## Purpose

Use the remainder of 2026 to stabilize one proven operating path, reduce cognitive and administrative load, reconcile what already exists, and enter 2027 with clear project, financial, legal, and lifestyle boundaries.

ChatGPT Plus is used as an organizing and reconciliation tool—not as a substitute for legal, medical, tax, housing, or other professional judgment.

## One active path

**Resident-led interactive experience → PIXIE/provenance workflow → documented evidence → public case study → repeatable 2027 offering**

Until this path is completed, new repos, major integrations, partnership tracks, or speculative expansions stay parked unless they directly unblock the pilot.

## Project status rules

Every Loptr Lab item must be marked as one of:

- **Active** — required for the current pilot or reconciliation.
- **Supporting** — useful infrastructure already serving the active path.
- **Blocked** — cannot move until a named dependency is resolved.
- **Parked** — valid idea, but not part of the current operating path.
- **Archived** — preserved for history, not active development.

For features and claims, use:

- **Implemented**
- **Tested**
- **Proposed**
- **Not yet verified**

Do not describe proposed features as implemented.

## End-of-year work phases

### Phase 1 — Pilot and proof
**Now through October 31, 2026**

- Complete Whittier pilot requirements.
- Keep attendance intentionally small.
- Document accessibility, participant flow, time, cost, and cleanup needs.
- Use PIXIE/provenance methods to capture decisions and revisions.
- Run the event independently of any artist participation or endorsement.
- Record what actually worked.

**Done when:** one resident-scale event has been completed and documented.

### Phase 2 — Project reconciliation
**November 2026**

- Inventory repos, sites, blogs, prototypes, domains, presentations, and integrations.
- Assign each item one project status.
- Remove duplicate or competing entry points.
- Separate implemented/tested work from proposed backlog.
- Identify one canonical public explanation of Loptr Lab.

**Done when:** every active asset has an owner, purpose, status, and next action—or is parked.

### Phase 3 — Financial, legal, and governance close
**December 2026**

Maintain separate records for:

- personal funds;
- Loptr Lab sole-proprietor/self-employment activity;
- owner-funded project expenses;
- reimbursements;
- fiscally hosted/Open Collective funds;
- grants or sponsorship funds;
- actual earned business income.

Do not retroactively relabel personal spending as company spending.

Also reconcile:

- permissions and licenses;
- privacy/consent records;
- accessibility decisions;
- legal/housing correspondence;
- fiscal-host decisions;
- debts and payment obligations;
- contracts or commitments;
- unresolved outside dependencies.

**Done when:** 2026 can be explained from the records without reconstructing events from memory.

## 2027 admission gate

No project or feature returns to active development unless all are true:

1. A specific user or participant is identified.
2. The outcome is clear.
3. Existing resources can support it.
4. It does not depend on an uncommitted outside party.
5. There is evidence from the pilot or prior work that the problem is real.
6. The work has a defined stop condition.
7. The project can be documented without mixing personal and project finances.

## Lifestyle operating rules

These are operating constraints, not optional productivity goals:

- Maximum **one major administrative block per day**.
- Administrative blocks target **45–60 minutes**.
- Maintain **one no-project day each week**.
- Protect a regular sleep window.
- Eat before long administrative or development sessions.
- Stop opening new research threads when the current task can be completed without them.
- Use reminders and written queues so unresolved work does not have to stay active in memory.
- When overloaded, reduce active work before adding a new system.

## Weekly ChatGPT Plus workflow

The weekly review should produce no more than five priorities:

1. financial/debt item that actually needs action;
2. legal or housing deadline due soon;
3. single Loptr Lab active-path priority;
4. one home/lifestyle stability priority;
5. what can wait.

The weekly review should not reactivate parked work unless a blocker has been resolved.

## Reconciliation ledger

Maintain four sections:

### Projects
Project, status, purpose, canonical link, next action, stop condition.

### Evidence
Implemented/tested/proposed status, source, date verified, unresolved question.

### Money
Date, amount, source, destination, classification, supporting record, personal/project/fiscal-host status.

### Obligations
Deadline, responsible party, required action, evidence of completion, follow-up date.

## 2027 operating principle

**Finish, document, reconcile, then expand.**

Loptr Lab should enter 2027 with fewer active commitments, stronger evidence, clearer financial separation, and one repeatable operating model rather than a larger backlog.
